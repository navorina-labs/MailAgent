How it works

Three API calls

01Inbox

Create an inbox

mailagent_create_inbox returns a unique address for the run.

02Your app

Submit your form

The agent enters the address in your signup, login, reset or invite form.

03Result

Get the action

mailagent_verify_signup waits for the email and returns agent.primaryAction.

Response

Structured result for the agent

primaryAction has type, value and instruction. On timeout, the response lists received subjects, the match count and a debug URL.

MCP tools REST reference 
await mailagent_verify_signup({

FAQ

FAQ

Does my app need changes?

No. Your app sends email as usual to the Mail Agent address.

What if the email does not arrive?

The timeout response lists received subjects, the match count, a suggested subjectContains and a debug URL. Troubleshooting

Can I test without sending real email?

Yes. POST /v1/inboxes/:id/simulate injects a test email without SMTP.

Can I use my own domain or self-host?

Yes. See custom domain and self-host.

Is Pro billed automatically?

No. Billing is not connected yet. Pro is enabled manually on request.
